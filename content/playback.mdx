## How playback is structured

The daemon keeps two sources of tracks:

1. **The user queue** — tracks you explicitly play or enqueue. The
   currently-playing entry sits at index 0 and is removed once it finishes or
   you press Next.
2. **The default list** — the whole library (title-sorted or shuffled). When
   the user queue is exhausted, the daemon continues with the default list.

Clearing the queue (`D`) disables the default list fallback until you
explicitly play or enqueue again.

## Volume & mute

- `+` / `=` — volume up
- `-` — volume down
- `m` — toggle mute

Volume range is 0–100 and is persisted across restarts. Each `+`/`-` press
changes it by 5. The CLI equivalents are `gtm --cli volume <vol>` and
`gtm --cli mute`.

---

## Seeking

- `.` — seek forward
- `,` — seek backward

CLI: `gtm --cli seek <seconds>`. Each `.`/`,` press seeks **±5 s**; repeated
presses accumulate and are coalesced into a single daemon seek, flushed 160 ms
after the last press. The daemon separately re-anchors client clocks roughly
once per second so the TUI position never drifts by more than a fraction of a
second.

:::note
Live streams (radio, internet radio) do not support seeking back. Seeking
forward to the live edge is generally safe.
:::

## Queue

The queue is a picker overlay opened with `Alt+q`. From the queue you can:

- `d`/`Del` — remove an entry
- `Ctrl+J` / `Ctrl+K` — move an entry (in queue-move mode)
- `Enter` — confirm a move
- `Esc` — cancel a move

CLI:

```bash
gtm --cli queue                              # print the queue
gtm --cli queue-add ~/Music/song.flac        # add to queue (play-next)
gtm --cli queue-remove 0                     # remove by index
gtm --cli queue-move 0 2                     # move entry
gtm --cli queue-clear                        # clear the queue
gtm --cli queue-set ~/Music/*.flac --start-idx 0   # replace the queue
```

:::note
Queue indices are positions in the **merged view** — the user queue first,
then the default library list — not queue-relative. With an empty user queue,
`queue-remove 0` removes the first track of the library list. Out-of-range
indices are silently ignored.

`queue-add` inserts *play-next* (right after the current entry) unless you pass
`--position <INDEX>`.
:::

Adding directories recursively scans for audio files. Library scans pick up
`mp3, flac, ogg, wav, m4a, aac, opus`.

:::caution
`queue-add` also accepts the `wma` extension, but gtm has no WMA decoder. A
`.wma` file enters the queue cleanly and fails at playback time instead, with no
error at the point you added it.
:::

## Repeat & shuffle

- `r` / `R` — cycle repeat: Off → One → All
- `S` — toggle shuffle (note: lowercase `s` is Stop)

Repeat modes:

| Mode | Behavior |
|------|----------|
| **Off** | Play through the queue once, then stop |
| **One** | Repeat the current track |
| **All** | Repeat the whole queue |

Shuffle affects both the user queue and the default library list. The order
is randomized in place; you cannot "un-shuffle" back to a previous order.

CLI: `gtm --cli repeat off|one|all`, `gtm --cli shuffle`.

## Sleep timer

The sleep timer counts down a set number of minutes, then **stops playback**
(silences the mixer, cancels any Spotify Web stream, and clears crossfade
standby).

- `Alt+z` — open the Sleep Timer picker (a slider; `←`/`→` or `h`/`l` step by 5
  minutes, `-`/`+` by 1, and `i` switches to numeric entry)
- CLI: `gtm --cli sleep-timer <minutes>`
- CLI: `gtm --cli cancel-sleep-timer`

The remaining time is shown in the footer `SleepTimer` module and ticked
once per second. Arming a new timer replaces the old one; cancel bumps an
internal generation counter so a stale countdown cannot stop playback.

:::note
By default the timer hard-stops at expiry — it does **not** fade out
gradually. The picker's immediate-stop toggle instead defers the stop to the
natural end of the current track, in which case a crossfade that would revive
playback is refused.
:::

## Low-power mode

Low-power mode has **no default key binding**. Reach it with the CLI or by
binding `toggle_low_power` in `config.toml` (see
[TUI](/tui/#keybindings)). `z` toggles **Zen** mode, not low-power.

Enabling low-power pauses playback and eases up on background work (it also
cancels any armed sleep timer). Disabling just clears the flag so you can
play again.

CLI: `gtm --cli low-power` (toggles), `gtm --cli low-power --set on|off`.

## State persistence

The daemon persists the following to `state.json` on every change:

- Queue and cursor
- Volume, mute
- Repeat mode, shuffle
- Mono downmix flag
- Crossfade configuration
- Gapless flag (see [Crossfade](/crossfade/))
- Dynamic-mode and scrobble configuration
- Audio settings: EQ preset and on/off, output device, reverb, loudness mode,
  pre-gain

The current track and position **are** persisted and resumed on restart; the
sleep timer and low-power mode are not.

---

## Limitations

- Volume is an integer 0–100, and each `+`/`-` press changes it by 5.
- Shuffle cannot be reversed to a prior order.
- Live sources do not support seeking backward.
