## Resolution order

For a local track, the daemon serves cover art in this order:

1. **Embedded artwork** from the library row's `cover_path`, else an audio
   **sidecar** next to the file (`<stem>.jpg|.jpeg|.png|.webp`), else the
   queue entry's already-known `cover_path` (Spotify playlist syncs point this
   at CDN art specifically so a playing track is never left blank)
2. For `radio://` URIs, the station's own art — see the four-step chain under
   [Limitations](#_limitations)
3. If a **Spotify** account is linked and the provider is `Auto` (default)
   or `Spotify`, a Spotify search for the **largest artwork variant the API
   offers** (there is no fixed 640×640 assumption)
4. The configured **metadata provider(s)** (MusicBrainz then Deezer by
   default, see below)

Each metadata lookup is bounded by a 5-second timeout; the Spotify lookup
is bounded at 8 seconds. Misses fall through instead of stalling the view.

## Providers

| Provider | Source |
|----------|--------|
| **MusicBrainz** | Cover Art Archive (`https://coverartarchive.org`) |
| **Deezer** | `https://api.deezer.com/search` |
| **Spotify** | Spotify API (requires a linked account) |

**Artist portraits** are a separate resolution path: Deezer's `/artist` image
first, then a Spotify artist search. They cache under `artist_covers/` with
their own 30-entry / 2 MiB in-memory LRU and a different key
(`sha256("artist:<name>")`), so artist art is stored and evicted independently
of album art.

`CoverProvider::Auto` (the default) starts with MusicBrainz and falls back
to Deezer. `Deezer` sweeps Deezer first, then MusicBrainz.

:::note
Spotify is only used as a **cover source with a linked account**. It is
preferred ahead of the fallback provider when linked and the provider is
`Auto` or `Spotify`.
:::

## Choosing a provider

Very small and very low-resolution images are rejected — a candidate whose
width **or** height is below **300px** (`MIN_COVER_DIM`) is discarded in
favor of the next source.

From the TUI:

- `Alt+,` → Settings → Playback → `Cover Source` — cycles
  auto → musicbrainz → deezer → spotify → auto and pushes the change live

Or set it in `config.toml`:

```toml
cover_provider = "deezer"
```

The daemon accepts a few lossy spellings for resilience: `deezer`,
`musicbrainz`, `mb`, `musicbrainz/cover-art-archive`, `spotify` — anything
else falls back to `Auto`. The provider can also be changed at runtime via
IPC without a restart.

## Caching

Covers are cached in two layers:

| Layer | Bound |
|-------|-------|
| In-memory LRU | 64 entries, ≤ 8 MiB (artist tiles: 30 entries, ≤ 2 MiB) |
| Disk (`$XDG_CACHE_HOME/gtm/covers/` + `artist_covers/`) | combined budget, default 512 MiB (`cover_cache_mb`); oldest-by-mtime pruned when over |

Each Deezer request is preceded by a fixed 200 ms sleep (`RATE_LIMIT_MS`) — a
floor, not a global rate limiter. Concurrent callers each pay their own 200 ms
rather than being spaced out, and MusicBrainz, Spotify and artist-image
requests are unthrottled.

The album-art viewer and the album cover tiles in the library both read
through this same cache, so artwork appears without re-fetching.

## Album art viewer

A track cover popup opens when the track pane gains focus, showing the same
cover the now-playing pane uses. In a normal TUI pane the cover is
letterboxed to the available height.

For a full-screen artwork viewer press `z` for Zen mode and cycle to the cover
surface — `z` cycles cover → visualizer → lyrics. There is no cover-only key.
