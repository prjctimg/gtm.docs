## Best-effort enrichment

Embedded tags in audio files are not always reliable: artists like "Feat.
DJB", genres rendered as "unknown", or album names truncated. The daemon
treats provider lookups as **best-effort enrichment**: any track whose tags
are missing, partial, or filename-like (e.g. a bare filename with no real
tags) gets probed by the **metadata-sync pass** — `gtm --cli metadata-sync`, or
Settings → System → Sync Metadata. **Scanning itself never contacts a
provider.**

:::caution
The gate is per-track, not per-field. Once a track qualifies and Deezer
answers, title, artist, album, genre, year, track number and `album_id` are
written **wholesale** — to both the file tags and the database. Embedded values
survive only because the *whole track* was gated out, not because individual
fields are protected.
:::

The result is both:

1. Written back into the **audio file tags** (`lofty`: title, artist,
   album, genre, year 1000–9999, track > 0, cover PNG/GIF/JPEG)
2. Recorded in the **library database**

The only guard is `tags_need_enrichment` — empty title, artist or album, a
title still equal to the raw filename stem, an empty genre, or `track_number
<= 0`. It is re-evaluated on **every** sync run and nothing is memoised
between runs, so a file that still looks incomplete is re-queried each time.

## Deezer

`https://api.deezer.com/search`

- Used for both metadata enrichment and **cover art** (see
  [Cover Art](/cover-art/))
- Requests are **rate-limited to one per 200 ms**
- Quietly degrades: a failed lookup just warns and leaves existing metadata

---

## MusicBrainz

`https://coverartarchive.org` (Cover Art Archive) and the standard
MusicBrainz web-service endpoints.

- Used for cover art and album metadata
- Artwork candidates below 300×300px are rejected
- The whole MusicBrainz→Deezer fallback shares **one 5 s budget**; each
  provider's own HTTP client separately times out at 15 s. Spotify's lookup is
  capped at 8 s. Results are cached like covers

## Last.fm scrobbling

Last.fm integration records your **scrobbles**: what you listen to, as
`track.scrobble` / `track.updateNowPlaying` per the Last.fm Web API (base
endpoint `https://ws.audioscrobbler.com/2.0/`). It also implements
`track.love` / `track.unlove`, and `gtm --cli love` also immediate-scrobbles
the current play session.

```bash
gtm --cli setup lastfm      # enter your API key + secret
gtm --cli love              # love the current track (also scrobbles it)
gtm --cli unlove            # remove the love
gtm --cli scrobble          # toggle scrobbling on/off
```

In the TUI: `*` toggles love and `&` toggles scrobbling.

### Setting it up

```bash
gtm --cli setup lastfm
```

The guided flow:

1. Create an API application at `https://www.last.fm/api/account/create`
   (API key + secret + callback URL)
2. Enter the key and secret (stored with the daemon)
3. The browser opens `https://www.last.fm/api/auth/?api_key=<your-key>` to
   grant access
4. The daemon captures the callback token and swaps it for a session

The loopback callback is served on `127.0.0.1:8991` (`$GTM_LASTFM_PORT` to
override) with a five-minute window, and the redirect is matched on a `token`
query param. If the browser does not redirect, you can paste the token from the
address bar instead — the CLI accepts a manual token on stdin.

After that, re-running `gtm --cli setup lastfm` or `gtm --cli scrobble` reports
scrobbling state (`Ready (scrobbling enabled|disabled)`, `API key set, not yet
authorized`, or `Not configured`). `gtm --cli status` shows playback state only
— Playback, Track, Volume, Repeat, Shuffle and Queue — and no Last.fm
information. Now-playing updates and completed-track scrobbles are pushed
automatically.

:::tip
Scrobbling needs an active last.fm session; `lastfm.status()` shows
`ready`/`not_ready` and the CLI `setup` flow handles re-auth.
:::

## Metadata sync

```bash
gtm --cli metadata-sync                       # probe all library tracks
gtm --cli metadata-sync ~/Music/weird.flac    # probe a single file
```

Runs the enrichment pass immediately for a file or the entire library —
handy after adding a file with terrible tags.
