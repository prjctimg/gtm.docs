## Linking your account

Spotify integration uses OAuth PKCE and a local redirect server. Once
linked, gtm can search, stream, and sync your playlists.

### CLI

```bash
gtm --cli setup spotify                    # guided setup (TUI chooser or --cli)
gtm --cli spotify login [client_id]        # browser OAuth flow on port 8990
gtm --cli spotify login <client_id> --port 9100
gtm --cli spotify connect <access_token>   # link with an already-obtained token
gtm --cli spotify status                   # show connection status
gtm --cli spotify disconnect               # unlink
```

OAuth details:

- Redirect port **8990** (or `$GTM_SPOTIFY_PORT`) — the server listens on
  `http://127.0.0.1:8990/login` for the code.
- `client_id` is **optional**. Leave it blank to authorise against librespot's
  public desktop app; a supplied id takes precedence over a stored secret, and
  whichever is used is persisted so refreshes keep the same app.
- Login window is capped at **120 seconds** (the CLI then waits up to 180 s for
  the link to land, but the flow has already failed by then).
- 14 scopes, the important ones being `streaming` and `app-remote-control`
  (required for native librespot playback — login5 rejects a token without
  `streaming`), plus playback-state, modify-playback-state, currently-playing,
  playlist read **and** modify (public/private), user-library read **and**
  modify, and user profile (private/email).
- **No `offline_access` scope** — Spotify does not define it for this flow;
  refresh tokens are handled internally.

### TUI

Open the setup/service picker (`Alt+x`) and choose Spotify; follow the
prompts. The TUI opens your browser to the Spotify authorization page; when
you land on the local redirect, the daemon captures the code and exchanges
it for a token automatically.

## Search & streaming

- `Alt+s` — open the Spotify search picker

Search issues four independent API calls covering tracks, albums, artists
**and playlists**, merged into one list — a failure in one kind does not hide
the others. Spotify's per-request `limit` is capped at 10 (since its February
2026 migration), so you get up to 10 tracks plus 5 each of albums, artists and
playlists, all backed by the official Search API.
Entering a track streams it through the Spotify Web/zlib decoder without ever
storing the track locally.

Streams use the same EQ, reverb, volume, and crossfade pipeline as local
files. Position and state are broadcast the same way, so the TUI treats
them identically.

## Playlist sync

```bash
gtm --cli spotify sync                    # sync all linked playlists to library
```

Your Spotify playlists appear in the **Library → Spotify** category. Syncing
is additive and caches the track list so the category is usable offline
(see below). New playlist edits sync on the next `spotify sync`.

## The Spotify Web cache

`spotify.json` (mode 0600) and a sibling `spotify_client_id` in the **daemon
config dir** hold the access/refresh token and the authorised client id, both
mirrored into the OS keychain — so a linked account does not require
re-authorization every launch. Playlists are cached **in memory only**.

`~/.cache/gtm/spotify/` is a different thing entirely: it is the yt-dlp audio
cache used by the Spotify→YouTube fallback for tracks librespot cannot stream,
and it is only populated when the `youtube` feature is on.

## Covers from Spotify

When a Spotify account is linked, a lookup for the largest artwork variant the
API offers is tried **before** the MusicBrainz/Deezer fallback (for the default `Auto`
cover provider). Covers found this way are cached exactly like any other
cover. See [Cover Art](/cover-art/).

---

## Limitations

- The `youtube` feature must be enabled for the decipher step (same restriction as YouTube on Android builds).
- Search returns a bounded set — 10 per kind, see above.
