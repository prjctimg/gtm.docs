## Resolution order

When a track starts, the daemon resolves synced lyrics (`.lrc` format) in
strict priority order:

1. **`.lrc` sidecar** next to the audio file (`.srt` and timed `.json`
   sidecars are also accepted)
2. **Offline cache** — previously fetched `.lrc` files persisted on disk
3. **LRCLIB exact match** — `/api/get` by artist + title
4. **LRCLIB search** — `/api/search`, fuzzy-matched server-side
5. **LRCLIB title-only search** — last resort when the artist is unknown

Fuzzy matching uses a Jaro–Winkler similarity of ≥ **0.75**
(`FUZZY_THRESHOLD`) after normalizing artist/title names.

```
sidecar (.lrc/.srt/.json)
  → offline cache
    → lrclib exact
      → lrclib search
        → lrclib title-only
```

Sources 3–5 hit **LRCLIB** (`https://lrclib.net/api`).

:::note
An empty or malformed sidecar does **not** shadow the offline cache or the
network — a broken sidecar falls through instead of blocking lyrics.
:::

## Sidecar files

Name a lyrics file after the audio file and it is picked up automatically:

```text
track.flac
track.lrc      ← matched by filename stem
```

`.srt` and timed `.json` sidecars are also recognized. There is **no encoding
detection**: a sidecar is read as strict UTF-8, and one that fails to decode is
simply skipped (the offline cache and the network are still consulted).

You can also pass a sidecar explicitly by opening it from the file picker —
it attaches as synced `.lrc` data for the current track.

---

## Offline cache

Fetched lyrics are written as `.lrc` files so they are available offline on
future plays. Cache entries are keyed by a sanitized `Artist - Title` slug
plus a small hash suffix, stored in the XDG cache dir:

```bash
ls ~/.cache/gtm/lyrics/
```

The cache is consulted before any network fetch, which is why the second
play of a track is usually instant.

:::tip
Point the cover-art cache at the same reasoning: local-first, network only
when the local copy is missing.
:::

## Timing & sync

- The lyric view auto-scrolls as playback advances, and re-syncs its clock
  roughly once per second.
- During crossfade, the lyric auto-scroll cues toward the incoming track.

The daemon replies to each lyrics request with a `DaemonRes::Lyrics`; there is
no `lyrics` **event**. The TUI tags every request with a generation counter, so
a late reply is discarded rather than flashing the wrong lyrics.

Press `[` / `]` to nudge the lyric clock by up to ±120 s when lyrics are early
or late. The first nudge re-engages auto-follow and raises an offset toast.

## CLI

```bash
gtm --cli status --stream   # shows the current track's active lyric line
gtm --cli lyrics "artist - title"   # look up lyrics for any track
gtm lyrics "artist - title"  # search LRCLIB and print
```

The standalone `lyrics` command takes a **required** `artist - title` query
string — there is no no-argument form, so `gtm --cli lyrics` on its own is a
usage error. Any subcommand implies CLI mode, so the `--cli` flag is optional
there.

---

## Limitations

- Fuzzy matching thresholds mean very new or obscure releases may miss and fall through without displaying lyrics rather than showing wrong ones.
