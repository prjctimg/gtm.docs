## Availability

MPRIS (D-Bus media player interface) is part of the `gtmd` binary behind
the **`mpris`** cargo feature — **enabled by default**. Uninstall with:

```bash
cargo build --release --no-default-features --features youtube
```

On the session bus, media keys, GNOME Shell, KDE Plasma Now Playing, and
any MPRIS-aware app can control gtm without touching the TUI.

Installation is automatic when the DAEMON is built with the feature: the
MPRIS server starts on daemon startup and mirrors live playback state.

---

## Bus & object

| Property | Value |
|----------|-------|
| Bus | session D-Bus |
| Bus name | `org.mpris.MediaPlayer2.gtm` |
| Object | `/org/mpris/MediaPlayer2` |
| Interfaces | `org.mpris.MediaPlayer2`, `org.mpris.MediaPlayer2.Player` |

There is exactly one MPRIS instance, owned by `gtmd`. If a second instance
is started while one is live, it is killed so the bus name stays unique.

The MPRIS server subscribes to the daemon's event stream, so callers see
nothing beyond real gtm — no duplicated state.

## What you can do

The `Player` interface, mapped 1:1 to daemon IPC:

| Action | MPRIS method |
|--------|--------------|
| Play / Pause / Toggle | `Play`, `Pause`, `PlayPause` |
| Stop | `Stop` (releases the stream, fires `track_ended` cleanup) |
| Next / Previous | `Next`, `Previous` |
| Seek | `Seek(offset_us)` — relative in microseconds |
| Set position | `SetPosition(track_id, position_us)` (absolute, µs) |
| Loop | `SetLoopStatus("None"\|"Track"\|"Playlist")` |
| Volume | `Volume` property |
| Shuffle | `Shuffle` property |
| Rate | `Rate` / `MinimumRate` / `MaximumRate` (1.0 — playback speed is not mapped) |

Read-only introspection mirrors gtm state:

- `PlaybackStatus`: `Playing` / `Paused` / `Stopped`
- `Position`: microseconds, refreshed live from `time_pos`
- `Metadata`: track id, title, artist, album, length, artwork URL
- `CanSeek`, `CanControl`, `CanPlay`/`CanPause`, `CanGoNext`/`CanGoPrevious`

`CanPause` is reported `true` unconditionally. Pausing is only meaningful
for seekable sources — the TUI itself blocks pause for live streams (radio,
podcasts).

## Desktop integration

No configuration needed: any `.desktop` app or GNOME/KDE media controls
pick up the session-bus name and list gtm alongside other players.
`playerctl play-pause` works out of the box.

```bash
playerctl status
playerctl position
playerctl play-pause
playerctl next
```

---

## Limitations

- Requires a session D-Bus and the `mpris` feature.
- MPRIS is strictly one instance; concurrent `gtmd`s conflict (by design).
