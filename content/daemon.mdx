## Architecture

gtm is two processes:

| Process | Binary | Role |
|---------|--------|------|
| **Daemon** | `gtmd` | Decodes audio, drives the state machine, owns the mixer/EQ/crossfade, and all integrations (Spotify, Last.fm, covers, lyrics, podcasts, radio, MPRIS) |
| **Client** | `gtm` | TUI/CLI that talks to the daemon over a Unix socket |

The daemon keeps playing even when the TUI closes. The client auto-starts
it on first connection.

---

## Starting & stopping

The client starts the daemon automatically. For an explicit start:

```bash
gtmd                  # runs in the foreground — give it a terminal of its own
gtmd -v               # verbose logging
gtmd --test-mode      # for debugging, see below
```

gtmd does **not** daemonize itself — it stays attached to your terminal and
logs to `gtmd.log`, not to stdout. It is the *client* that detaches when it
auto-starts the daemon for you.

`--test-mode` is a debugging harness: no log file, a null audio mixer, no
single-instance guard, no MPRIS, no network probes, and no state load or save.

`--version` / `-V` prints the version and exits. It is handled before
argument parsing rather than by the flag parser, so it does not appear in
`--help`.

Orderly stop from a client:

```bash
gtm --cli quit
gtm --cli check-health
gtm --cli ping
```

## Unix sockets

The daemon listens on a command socket. A `gtmd.pulse` sidecar socket carries a
read-only, length-prefixed MessagePack event stream. Socket path resolution
order:

1. `$XDG_RUNTIME_DIR/gtm/gtmd.sock`
2. `/tmp/gtm-$USER/gtm/gtmd.sock`
3. `$TMPDIR/gtm/gtmd.sock`
4. Termux: `$PREFIX/tmp/gtm/gtmd.sock`
5. `$HOME/.gtm/gtm/gtmd.sock`
6. `$TMPDIR/gtm/gtmd.sock` via the system temp dir, when `HOME` is unset

Override with `gtmd --socket <path>`. Both the command socket and its
`<socket>.pulse` twin derive from that path. A stale socket is removed at
startup.

Requests are **newline-delimited JSON** over the Unix socket, one request ↔
one typed response. The response subtypes (`DaemonReq` / `DaemonRes`) keep the
protocol forward-compatible. The unsolicited *event* stream is a separate
framing: 4-byte length prefix followed by a MessagePack-encoded
`DaemonEvent`.

Multiple clients (TUI + `gtm --cli` + playerctl) can attach and all share the
one `.pulse` event socket.

## Data files

Under the XDG data dir (`~/.local/share/gtm/`):

| File / dir | Purpose |
|------------|---------|
| `library.db` | SQLite metadata for scanned tracks |
| `state.json` | Persisted state: queue and cursor, current track, position and resume flag, volume, mute, mono, repeat, shuffle, crossfade, gapless, `low_power` and `dynamic_mode`, scrobble toggle, audio settings (EQ, device, reverb, loudness, pre-gain) |
| `gtmd.log` | Daemon log, **truncated on every start** (only `--test-mode` skips it) |
| `audio/` | Default library audio dir |

Cache dir (`~/.cache/gtm/`):

| File / dir | Purpose |
|------------|---------|
| `covers/` | On-disk cover cache (capped at 512 MiB, evicts oldest by mtime) |
| `artist_covers/` | Artist-tile cover cache |
| `lyrics/` | Fetched `.lrc` cache |
| `spotify/` | yt-dlp audio cache for the Spotify→YouTube fallback |

Downloads: `dirs::audio_dir()/gtm/downloads` (usually `~/Music/gtm/downloads`).

Config dir (`~/.config/gtm/`):

| File | Purpose |
|------|---------|
| `config.toml` | Client settings incl. `cover_provider` |
| `footer.toml` | Footer presets |
| `themes/*.toml` | User themes |
| `podcast.json` | Podcast subscriptions |
| `radios.toml` | Custom radio stations |
| `spotify_stream.json` | Resolved stream URL for the active Spotify track |

## Status endpoint

Alongside the Unix socket, `gtmd` serves a read-only JSON view of the current
track over plain HTTP, so a script, home-screen widget or web page can read what
is playing without attaching to the IPC socket. It is on by default on loopback
and controlled by the `web_addr` key in `config.toml` — see
[Daemon-read keys](/configuration/#daemon-read-keys) and
[Status endpoint](/configuration/#status-endpoint) for the payload and the
address forms.

## Logs

`gtmd.log` lives next to `library.db` in the data dir and is **truncated on
every start** — nothing survives a restart except within a single run. Logging
is on for every run except `--test-mode`, which writes no log at all.

`RUST_LOG` takes an env-filter directive and replaces the level derived from
`--verbose` wholesale, so it overrides that flag rather than adding to it:

```bash
RUST_LOG=gtmd=debug gtm
RUST_LOG=gtm=info,gtmd=warn gtm
```

Without `RUST_LOG`, `--verbose` selects `debug` and otherwise `info`, and
`rspotify_http` is pinned at `warn` so access tokens never reach the log.

## CLI reference

`gtmd` takes six flags, all listed in [CLI Reference](/cli/#gtmd):

| Flag | Effect |
|------|--------|
| `--socket <PATH>` | Unix socket path; the pulse socket becomes the same path with a `pulse` extension |
| `--config <DIR>` | Relocates **all three** roots at once — config, data, and cache (the last becoming `<DIR>/cache`) |
| `--library <PATH>` | Parsed and then ignored — see below |
| `--backend <BACKEND>` | `rodio` or `pulseaudio` |
| `-v`, `--verbose` | Debug-level logging |
| `--test-mode` | Ephemeral socket, no log file, no persisted state, a null mixer, and no network fetches |

`--library` changes nothing. The scanned directories are fixed: `data_dir/audio`,
`~/Music` if it exists, and the shared-storage music directories under Termux.
The database is always `data_dir/library.db`.

`--backend pulseaudio` needs a build with the `pulseaudio` Cargo feature. Without
it the flag is accepted but silently ignored and Rodio is used.
