## Audio backends

gtm ships two audio backends behind a common `Mixer` interface:

| Backend | Feature | Notes |
|---------|---------|-------|
| **Rodio** | (default) | Cross-platform, ALSA/CoreAudio via cpal |
| **PulseAudio** | `pulseaudio` | Native PulseAudio streams; auto-selected on Termux |

The backend also owns EQ, reverb, pitch-preserving speed, device switching,
and crossfade — one code path for every source (local files, Spotify,
remote streams).

### Supported formats

Decoding goes through Symphonia built with `all-formats` / `all-codecs`, so
the default build handles mp3, FLAC, WAV, AIFF, ALAC, Ogg Vorbis, Opus, AAC/M4A,
WavPack, APE and Musepack, with any other enabled codec (e.g. WMA) following
the same path. The library scanner accepts `mp3, flac, ogg, wav, m4a, aac,
opus`; the queue's directory walk additionally accepts `wma`.

### Selecting the backend

```bash
gtmd --backend rodio       # explicit
gtmd --backend pulseaudio  # explicit (needs a build with --features pulseaudio)
```

Without an explicit `--backend`, Termux builds auto-select PulseAudio so
audio can be output on Android; other platforms default to Rodio.

:::caution
`--backend pulseaudio` is accepted by any build, but the PulseAudio arm is
compiled only with the `pulseaudio` feature. In a default build the value is
silently ignored and you get Rodio.
:::

### Termux

At runtime on Termux, `gtmd` starts the PulseAudio server automatically.
If your build lacks the `pulseaudio` feature, a clear error suggests
rebuilding with `--features pulseaudio`.

## Output devices

- `gtm --cli audio-devices` — list available output devices
- `gtm --cli set-audio-device <name>` — switch output device
  (`default` restores the system default)

Switching restarts the output and stops playback, then persists the chosen
device so it survives restart. When a requested device fails to open, the
daemon falls back to the default.

The active device is shown in the footer `Device` module (and the `Backend`
module shows Rodio vs PulseAudio).

## Equalizer

The equalizer is a **15-band graphic EQ** using ISO 1/3-octave center
frequencies:

```
25, 40, 63, 100, 160, 250, 400, 630, 1000, 1600, 2500,
4000, 6300, 10000, 16000 Hz
```

Each band is a bell filter (default Q = 1.414, i.e. 1/3-octave bandwidth),
applied per sample in the audio engine with gains re-checked every 128
samples to avoid lock contention.

Each preset's curve is capped at **±4 dB**, and gtm then applies an automatic
headroom trim equal to −(largest boost) so EQ boosts can never clip. The
output is hard-clamped to ±1.0 — which is why a boost-heavy preset like
`Bass Boost` is audibly quieter by design.

### Presets

16 presets are built in:

| Preset | Preset |
|--------|--------|
| Flat | Electronic |
| Normal | Hip-Hop |
| Pop | Latin |
| Rock | Acoustic |
| Jazz | Podcast |
| Classical | Dance |
| Bass Boost | Headphones |
| Vocal | Speaker |

`Alt+e` opens the equalizer picker with a live mini-plot of each preset's
frequency response. `Enter` applies the selected preset. The EQ
on/off toggle lives under `Alt+,` (Settings → Playback). The footer
`EqPreset` module shows the active preset.

EQ presets are stored in `AudioSettings` (`eq_preset`, `eq_enabled`) and
persisted with the daemon state.

:::note
The `EqPreset::Custom([f32; 15])` variant exists in the state model but is
**not exposed in the TUI** — there is no per-band editing UI yet.
:::

## Reverb

A simple room model is available via `reverb_stereo(room_size, ...)`. It
defaults to **off**. The persisted `room_size` default is 0.5 (the mixer
bootstraps at 0.3 until the daemon applies saved settings), and the bound is
0.0–1.0. Reverb is applied by the daemon and toggled from Settings → Playback.

:::note
`room_size` is only read when a source is (re)started, so changing it does not
affect an already-playing track.
:::

## Visualizer

The visualizer renders live FFT data from the daemon's decoder: `audio_levels`
is **64 log-spaced bins from 30 Hz to 16 kHz**, produced by a 2048-point
Hann-windowed FFT over samples decimated 4:1 — so a fresh frame arrives roughly
every **186 ms** at 44.1 kHz, not every 16 ms. The daemon re-broadcasts the
latest 64 bins on a much faster ~16 ms poll, and it stops analysing entirely
while no TUI client is connected.

![Spectrum Visualizer Rendering Animation](/samples/spectrum-visualizer-demo.gif)

- `Ctrl+V` — toggle the visualizer
- `Alt+v` — open the preset picker (with a live preview)

### Visualizer presets

| Preset | Render style |
|--------|--------------|
| **Braille** (default) | Braille cells, color chosen per bar by amplitude |
| **Blocks** | Block columns with fine fractional heights (`▁…█`) |
| **Mirror** | Center-symmetric bars blooming outward from the middle axis |
| **Gradient** | Braille cells with a 4-step color ramp by amplitude |
| **Spectrum** | Log-mapped spectrum bars with peak-hold caps (falling `▔` marker) |
| **BarsDot** | Braille-stippled bars, each cell a 4×2 dot grid filled bottom-up |
| **ClassicPeak** | Classic falling peak caps over thin columns (launch/gravity/cap physics) |
| **Columns** | Dense thin interpolated columns, one glyph per terminal column |
| **Wave** | Braille oscilloscope over the decimated waveform ring (sine sweep when idle) |
| **Stereo** | Stereo L/R horizontal LED peak meters |
| **Retro** | 80s synthwave scene: striped sun, horizon, scrolling grid, audio-reactive wave |
| **Flame** | Doom-fire heat field rendered through Braille cells, colored by heat |

Rendering is frame-rate independent: bars use attack 0.65 / decay 0.45 (0.25
when idle), and when nothing is playing an idle sine-wave animation keeps the
view alive.

The visualizer only renders when the terminal is ≥ 80 columns wide.

The client's `visualizer_preset` config key sets the default preset
(`"braille" | "blocks" | "mirror" | "gradient" | "spectrum" | "barsdot" |
"classicpeak" | "columns" | "wave" | "stereo" | "retro" | "flame"`).

## Limitations

- PulseAudio is Linux/Android-only; macOS and Windows use Rodio.
