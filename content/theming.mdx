## Built-in themes

16 themes are built in:

| Theme | Type |

| Classic | dark |
| Chadrula | dark |
| One Dark | dark |
| Tokyo Night | dark |
| Tokyo Night Storm | dark |
| Catppuccin Mocha | dark |

| Everforest | dark |
| Kanagawa | dark |
| Kanagawa Lotus | light |
| Solarized Light | light |
| Solarized Dark | dark |
| Monochrome | dark |

Switch themes from the theme picker (`Alt+T` cycles **every registered theme**
— the 16 built-ins plus any of your own user themes, in load order — and sets
`theme_mode` to `"manual"`; `Alt+C` opens the full picker with live preview) or
persist a name:

```toml
# config.toml
theme_name = "Tokyo Night Storm"
```

The default theme is **Chadrula**.

## Theme mode & OS detection

`theme_mode` controls how the starting theme is chosen:

| Value | Behavior |
|-------|----------|
| `auto` (default) | Query the OS dark/light preference; pick a matching theme |
| `dark` | Force a dark theme |
| `light` | Force a light theme |
| `manual` | Keep the current theme; OS detection stays off until you return to `auto` |

`Alt+T` cycles `auto → dark → light → manual → auto`.

In `auto` mode the **client** detects the desktop preference, in this order:

1. `GTM_THEME_MODE=dark|light` env var (an absolute override)
2. GNOME `org.gnome.desktop.interface color-scheme` via `gsettings`
3. `GTK_THEME` (a trailing `-dark` means dark)
4. Omarchy `current/theme/colors.toml`

If every probe fails, the persisted `theme_name` is kept. Detection emits no log
line — to see the effective theme, read `theme_name` in `config.toml` or open
the theme picker (`Alt+C`), which badges light themes with ☀.

## User themes

Drop a TOML file into `~/.config/gtm/themes/` (or
`$XDG_CONFIG_HOME/gtm/themes/`) and it appears in the picker:

```toml
# ~/.config/gtm/themes/mytheme.toml
# The 18 required fields below (name + 17 colours) are REQUIRED. A file missing
# any of them fails to parse and is skipped silently — the theme never appears.
name = "My Theme"
bg = "#101014"
picker_bg = "#1a1b26"
fg = "#d0d0d8"
fg_dim = "#8888a0"
fg_bright = "#f0f0f8"
accent = "#7aa2f7"
error = "#f7768e"
warning = "#e0af68"
success = "#9ece6a"
selection_fg = "#101014"
selection_bg = "#7aa2f7"
border = "#414868"
border_active = "#7aa2f7"
volume_low = "#9ece6a"
volume_medium = "#e0af68"
volume_high = "#f7768e"
sidebar_active_border = "#7aa2f7"

# Optional (all shown with their fallbacks)
light = false              # auto-detected from bg luminance when omitted
pane_bg = "#16161e"        # defaults to bg
elevated_bg = "#1f1f27"    # defaults to picker_bg
muted_border = "#2e2e3a"   # defaults to border
secondary_accent = "#bb98ff"  # defaults to accent
tertiary_accent = "#9ece6a"   # defaults to accent
notification_border = "#7aa2f7" # defaults to accent
monochromatic = false      # defaults to false
```

Notes:

- `pane_bg` defaults to `bg`; `elevated_bg` defaults to `picker_bg`; `muted_border`
  defaults to `border`. These three are optional for back-compat with pre-C0 theme
  files.
- `secondary_accent` / `tertiary_accent` / `notification_border` fall back to `accent`.
- All colours accept `#rrggbb` hex.
- A user theme whose `name` matches a built-in **replaces** that built-in, which
  is the supported way to override a default. Duplicate names among your own
  files are not detected.

## Reactive theme

```toml
# config.toml
reactive_theme = true                # default: false
reactive_theme_intensity = 0.34      # default 0.34; bound 0.0–1.0
```

The picker steps intensity through five presets: `0.15`, `0.25`, `0.34`,
`0.45`, `0.6`.

With reactive theming on, the palette is **derived live from the
currently-played track's cover art**. The **client** extracts a dominant
palette (median-cut, 10 colours) on a background thread and blends it into the
base theme. It degrades gracefully to the base theme when no cover is available.

:::note
Reactive theming re-tints the *accents* — and those take the artwork colours
nearly verbatim, so `reactive_theme_intensity` does **not** damp them. The
intensity instead controls a faint ambient wash of the dominant colour laid over
`bg`, `pane_bg`, `elevated_bg` and `picker_bg`. Set it to `0.0` to leave
backgrounds entirely on the base theme.
:::

## Progress styles

| Style | Description |
|-------|-------------|
| **Seek Head** | Chasing tick at the playhead |
| **Classic** | Plain filled/unfilled bar |
| **Dots** | Dot matrix bar |
| **True Gradient** (default) | Each filled cell is color-interpolated across `accent → secondary_accent → tertiary_accent` |

Pick one with `Alt+p`, or set `progress_style` in `config.toml`. Unlike cover
source, progress style has **no row in the Settings pane** — the picker and the
config file are the only surfaces.

:::note
The serialized values are case-sensitive and have no serde rename: `SeekHead`,
`Classic`, `Dots`, `TrueGradient`.
:::

## Footer presets

The footer is split into **left** and **right** module groups. Three
built-in presets are provided:

| Preset | Modules |
|--------|---------|
| **Default** | Playback, Repeat, Shuffle, Volume, Speed, LowPower, Mono, Device, EqPreset, KeyAction, Notification, SleepTimer, Download (right: Queue, Time, System, Multiselect, Network, Source) |
| **Minimal** | Playback, Volume, KeyAction, SleepTimer (right: Time, System) — for Termux/small viewports |
| **Full** | Playback, Title, Repeat, Shuffle, Volume, EqPreset, Mono, Progress, KeyAction, SleepTimer (right: Queue, Time, System, Multiselect, Network, Source) |

Add your own in `~/.config/gtm/footer.toml` (or
`$XDG_CONFIG_HOME/gtm/footer.toml`):

```toml
# ~/.config/gtm/footer.toml
preset = [{ name = "My Footer", left = ["Playback", "Title", "Volume", "Speed", "EqPreset", "Device"], right = ["Time", "System"] }]
```

A legacy `middle` key still parses so older files load, but its modules are
**discarded** — move them into `left` or `right`. Unknown module names are
ignored and malformed files are skipped entirely.

Modules available (22):

```
Playback Title Volume Speed Repeat Shuffle Progress Queue KeyAction
Backend System EqPreset SleepTimer LowPower Mono Device Notification Time
Multiselect Download Network Source
```

- `Alt+,` → Settings → Footer Preset opens the preset chooser, which previews
  the selected layout live. Individual modules **cannot** be toggled in the TUI —
  edit `~/.config/gtm/footer.toml` to compose a custom preset.

The chosen preset persists; modules are rendered left-to-right with each
module's own color set built from the active theme.

## Icons

The command palette supports two icon styles:

```toml
# config.toml
icon_style = "mdi"    # Material Design Icons (default)
```

Only `mdi` is special-cased — **any** other value falls through to the
emoji/ASCII set, so there is no separate named `"emoji"` mode. On terminals
without a Nerd Font, set `GTM_NERD_FONTS=0` (or `false`/`no`) to force plain
ASCII glyphs everywhere, including the sidebar and Settings icons.

## Transparent mode

Two persisted booleans drop gtm's own background fills so your terminal
wallpaper shows through. Both default to `false` and both live in
`config.toml`:

| Key | Default | Effect |
|-----|---------|--------|
| `transparent_bg` | `false` | Drop the TUI's own background fill |
| `transparent_pickers` | `false` | Same for floating picker panels |

Toggle either in `Alt+,` → Settings → System.
